# 双层 seam 测试策略：引擎主 seam + UI 冒烟次 seam

测试分层：**引擎层（主 seam）**——纯 TS 零 DOM，Vitest 单测覆盖资源结算/购买/解锁/外交/事件/离线/存档迁移等全部核心逻辑；**UI 层（次 seam）**——Vitest + jsdom 冒烟，覆盖「状态 → 渲染」映射。测试标准：**给定状态 + action → 断言新状态/渲染结果**，不 mock 内部方法、不依赖 DOM 实现细节、不测实现路径。

**状态**: Accepted
**日期**: 2026-08-05（idle-game spec Testing Decisions 定稿，持续执行）
**证据**: `.scratch/idle-game/spec.md` Testing Decisions；测试文件按域镜像引擎模块（`buildings.test.ts`/`tech.test.ts`/`planets.test.ts`/`diplomacy.test.ts`/`save.test.ts`…）

## 背景

三层架构（ADR-0001）下，引擎零 DOM 是天然测试边界；UI 层若逐细节 mock 会退化为「测试实现」的脆性测试。需要一套可长期执行的测试纪律，让 727+ vitest 全绿成为每次改动的事实基准。

## 决策

1. **行为断言而非实现断言**：测试只构造输入（state + action/参数），断言输出（新 state 字段 / 渲染结果）；不 mock 内部函数、不断言「调用了谁」。
2. **确定性注入**：时间（`nowMs` 参数）、随机（`rng` 注入，ADR-0007 签名兼容）全部可注入——离线结算用可控时钟做确定性断言。
3. **UI 冒烟为次 seam**：jsdom 下「给定 state → render → 断言关键结构（data-* 契约）」，不测交互细节（交互由 session 行为测试 + E2E 语义化断言覆盖）。
4. **域镜像组织**：测试文件与引擎模块一一对应（一个域一个测试文件），域拆分（ADR-0002）后测试同步拆分。
5. **平衡不变量测试**：数学性质（如 ROI≡P、成本单调）用不变量断言钉死，防止调参悄悄破坏（ADR-0021）。

## 为什么

- 行为断言的可维护性远高于实现断言：重构（如 engine hub 收窄、dispatch 类型化）不破坏测试，除非行为真的变了——这是 6 次大规模重构仍全绿的前提。
- 双层 seam 覆盖「逻辑正确（引擎）+ 映射正确（UI）」，中间层（dispatch/监听）由 actions.test/session.test 行为测试补充，三层各司其职。
- 确定性注入是挂机游戏测试的基石：没有可控时钟与可控随机，时间推进/随机事件/攻占成功率都不可测。

## 后果

- 新增玩法必须自带行为测试，且「全量测试绿」是 merge 硬门槛（AGENTS.md 惯例）。
- 测试是 ADR 的活文档：数值决策（ADR-0021/0022/0023）都有不变量测试锚定，改参数先改测试。
- E2E 退役（ADR-0019）后，vitest 全绿成为**唯一**事实基准——测试质量的权重进一步上升。
