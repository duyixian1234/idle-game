# 攻占成功后返还部分兵力（conquest-refund）

攻占成功后返还 `⌊投入军力 × CONQUEST_MILITARY_REFUND_PCT⌋`（初值 50%）军力，受军力容量截断；失败全损。军力从"消耗品"转为"半回收资源"（半回收投资），缓解后期探索生成军事目标速率 > 自动攻占处理速率（60s/目标）的积压漏斗。

**状态**: Accepted（2026-08-12 spec：攻占军力返还，issue #14）
**证据**: `src/engine/conquest.ts:241-256`（settleOneConquest 成功分支返还）；`src/engine/balance.ts:299-308`（CONQUEST_MILITARY_REFUND_PCT）；`src/i18n/zh.ts:134`（cq.12 返还文案）；`src/engine/conquest.test.ts:510-610`（返还契约六例）；`src/engine/balance-simulation.test.ts:399-445`（三档永续性）

## 背景

1. **后期军事目标积压**：探索奖池每 roll 到 conquest 分支即生成 1 个军事目标（`exploration.ts:386`），cap = `2 + ⌊探索/10⌋` 随探索次数线性增长（`generate.ts:83-89`）；而自动攻占每 60s 冷却仅处理 1 个（`conquest.ts:305`），守卫 = `min(名义产出×40s, 容量/3, 产出×180s)` 锚定 40s 回充，叠加 raid 击退、探索派遣的军力竞争，形成"几十个目标排队等军力"的漏斗。
2. **军力是唯一容量资源**（`production.ts:183-184`，满员停摆）——无法囤积应对积压，且攻占成功后投入军力全部蒸发（原 `invested` 不返还）。

## 决策

1. **成本定位（非吞吐杠杆）**：返还率固定常量 `CONQUEST_MILITARY_REFUND_PCT = 0.5`，根因子化进 `balance.ts`——军力从"消耗品"转"半回收资源"（半回收投资），不改变单目标性价比量级。
2. **仅成功返还**：失败仍全损（"薄投搏运气"高风险高收益博弈语义保留）。
3. **受容量截断**：返还量 clamp 到剩余容量（`min(refund, cap − military)`），存量已超 cap（异常态）时返还 0、不压低既有存量——军力容量铁律不破。
4. **按 invested 返还**：按实际投入军力而非守卫值——防薄投刷军力（投 500 返 250，不按守卫 2000 返 1000）。
5. **fleetLocked 不参与**：舰队战力折算非军力消耗，结算时已释放锁定。
6. **统一结算管线**：`settleOneConquest` 成功分支一处改动，手动/自动、静态/动态/boss 全覆盖；离线（`settleOffline → settleConquests`）复用同函数自动继承。
7. **不与成长杠杆挂钩**：不随科技/层数增长，避免与攻占科技线（ADR-0051 产出 ×2/消耗 ×0.5）叠加失控。

## 为什么

- 返还 50% 后单目标净耗 = 50%×守卫 = 名义产出×20s < 自动攻占 60s 冷却 → **军力不构成吞吐瓶颈，积压漏斗由"军力产出"转移到"攻占冷却"**（吞吐上限 = 1 目标/60s，与设计一致）。
- 军力从一次性消耗变为半回收投资，让"军力投入"始终有残值——对自动攻占（投满必成）与手动薄投（成功后残兵归队）都平滑积压。
- 容量截断 + 返还率 <1 双保险：单目标净耗恒正（返还 ≤ 投入），连续攻占下军力不净增，防印钞（balance-sim 三档断言锁定）。

## 后果

- **UI**：无新交互；返还军力数值随捷报日志（`cq.3`）经 `cq.12` 文案输出（zh「返还军力 {a0}」/ en「Recovered {a0} military」）。
- **schema**：零变更——`invested` 已存于 `ConquestState`，返还率走常量，无迁移。
- **测试**：`conquest.test.ts` 新增返还契约六例（足额/薄投/截断/失败/fleetLocked/离线）；`balance-simulation.test.ts` 三档永续性断言（净耗回充时间 < 60s）。
- **平衡**：50% 为初值，balance-sim 三档基准（毕业/NG+5/普通通关）校验军力不净增后定稿；若某档出现净增则降档（如 30%）。
