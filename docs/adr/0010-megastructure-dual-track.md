# 终局抉择开放化：从「二选一互斥」到「终局工程双轨」，废弃字段保留兼容

终局内容从「两个究极建筑只能选一个（本周目硬锁）」演进为「**两座皆可建**的终局工程双轨」：星环冶炼场（建设流，全局产出 ×2^level，满级 ×1024）与跃迁枢纽（探索流，+3 派遣槽/收获 ×4/离线 12h）互为独立路线，各自可建、可叠加。存档字段 `megastructureChoice` 保留但**不再消费**（废弃语义），旧档历史值兼容读取。

**状态**: Accepted（2026-08-07 开放化）；旧互斥语义 superseded
**日期**: 2026-08-06（互斥初版，interstellar-buildings）→ 2026-08-07（双轨开放）
**证据**: commit `512bfd1`（终局抉择开放化为终局工程双轨）、`56caea4`（merge）；`src/engine/types.ts:324-325`（megastructureChoice 废弃注释）；`.scratch/interstellar-buildings/spec.md`

## 背景

初版设计是「只能买一个」的终局抉择：冶炼场 vs 枢纽二选一、本周目永久锁定、NG+ 重置可重选（interstellar-buildings spec User Story 11/12）。但 grill 后发现互斥的代价是**一条路线玩家永远看不到**——建设流玩家无法体验探索流内容，反之亦然；且「探索向增强」与「经济向增强」本不冲突，互斥缺乏玩法必要性。

## 决策

1. **双轨皆可建**：两座究极建筑独立建造、效果叠加（冶炼场 ×2^level 全局产出 × 枢纽探索增强），解锁门槛保持（通关 + 三星系间建筑各 ≥1 级）。
2. **效果门控 = 建筑存在性**：冶炼场效果由 `buildings.smelter` 存在性门控，枢纽由 `buildings.jumpgate` 存在性门控——不再依赖 `megastructureChoice` 字段。
3. **废弃字段保留兼容**：`megastructureChoice: 'smelter' | 'jumpgate' | null` 留在类型与存档中，不迁移删除（v7 旧档无损）；NG+ 仍重置为 null，但无任何逻辑读取它。
4. **NG+ 遗产公式更新**：`megastructureLegacyBonus` 改为两座建筑等级之和 ×1.5%（原按 chosen 建筑折算），预览与执行同源（ADR-0009 决策 1）。

## 为什么

- 双轨开放把「二选一」从内容封锁改为内容叠加，玩家决策从「选错后悔」变为「两条路线都玩」，符合挂机游戏长线目标。
- 保留废弃字段而非迁移删除，避免 v7 旧档迁移链增负——成本（一个永不读取的字段）远小于收益（迁移风险归零）。
- 「效果门控 = 建筑存在性」是更简单的领域模型：建造物存在即生效，无需额外状态位。

## 后果

- 两座终局建筑的平衡锚点独立：冶炼场满级 ×1024 全局产出 vs 枢纽 +3 槽/×4 收获——探索流与建设流各有一极，不再共享一个「抉择位」。
- 代码中 `megastructureChoice` 成为死字段，未来清理需走存档迁移（低优先，勿因美观破坏兼容）。
- NG+ 遗产改为双建筑求和后，双轨玩家的周目继承加成高于单轨——这是「两条路线都玩」的刻意激励。
