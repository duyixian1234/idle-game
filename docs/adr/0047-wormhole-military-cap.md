# 虫洞军力线：军力容量等级放大轴（每级 +10%，Lv10 ×2）

终局军事需求（攻占守卫随产出增长、探索 20 槽并行军力消耗、自动攻占 60s 投注）与军力容量供给（军港 200/座线性）在 infinite 阶段脱节——容量是后期真正的瓶颈，而唯一等级放大轴军械科技只到 Lv5（×1.5）。本 ADR 给虫洞（ADR-0042 的探索线建筑）追加第二条效果线：军力容量随虫洞等级放大，与军械科技并列。

**状态**: Accepted（2026-08-10，grill 一轮 5 决策 Q1-Q5）
**证据**: `src/engine/balance.ts`（`MILITARY_BASE_CAP` / `MILITARY_PORT_CAP` / `MILITARY_CAP_TECH_PER_LEVEL` / 新 `WORMHOLE_CAP_PER_LEVEL`）；`src/engine/production.ts`（`militaryCap` 公式追加虫洞因子、`productionReport` 军力行新增 `capSource` 容量来源提示）；`src/engine/exploration.ts`（`expeditionCost` 军力分支 `cap×2%`）；`src/ui/render/shared.ts`（`wormholeEffectText` 军力线文案）；`src/ui/render/build.ts`（升级预览）；`src/ui/bars.ts`（breakdown notes 渲染 `capSource`）；`src/i18n/zh.ts` / `en.ts`

## 背景

- **容量瓶颈**：`militaryCap = ⌊(100 + 200×军港) × (1+永久+声望) × (1+0.1×军械Lv)⌋`。军港是唯一数量流来源（200/座线性），军械科技是唯一等级放大轴（×1.5 @Lv5）。infinite 阶段满 20 槽并行探索需 ≈210k 军力，纯靠军港需 ≈537 座（乘数流 ≈1.95 时）——军港数量成为后期硬瓶颈，且新周目重置后重新爬楼成本高。
- **需求与供给脱节**：攻占守卫锚定军力产出（40s×产出）随兵营数量增长；探索单槽军力 = `min(1000, max(40, ⌊cap×2%⌋))`，容量同时锚定"能派多少军力"。容量不足直接卡死自动攻占投注与多槽并行派遣。
- **虫洞具备容纳条件**：虫洞是 infinite 深水区内容（结盟 ≥10 仅 infinite 可达——ended 静态派系封顶 8；成本兆级），与军力需求爆发时点重合，天然是"应对后期高需求"的挂载点。

## 决策

1. **机制落点（Q1=A）**：全局军力容量乘数——`militaryCap` 公式追加独立因子 `(1 + WORMHOLE_CAP_PER_LEVEL × 虫洞等级)`。**不使用**「每座兵营容量贡献」或「军港容量乘数」——那两种都引入「数量 × 等级」耦合，违反 ADR-0036 机制二分（普通建筑只走数量维度，unique 大件走等级维度）。虫洞是等级维度建筑，容量是全局池，全局乘数是唯一自洽方案。
2. **范围（Q2=A）**：只放大容量，不碰军力产出（兵营 0.5/s 不动）。攻占守卫锚定产出（`40s × nominalMilitaryProduction`），放大产出会让守卫/raid 消耗同步膨胀，与"缓解高需求"目标相悖。
3. **消耗锚定（Q3=A）**：接受消耗随容量等比例缩放——探索单槽军力 `cap×2%`、勒索/臣服门槛 `cap×40%/60%` 随容量放大而放大。这是现有 `cost-anchors-cap` 不变量的自然结果；且探索军力成本在 cap≥50,000 时已封顶 1000/槽，**封顶后的虫洞容量是纯释放**，对后期探索最友好。
4. **倍率（Q5=B）**：`WORMHOLE_CAP_PER_LEVEL = 0.1`（每级 +10%，Lv10 ×2）。与虫洞探索线「发现权重 +10%/级」同构——同一条建筑线上所有效果收益曲线一致，符合 ADR-0042 "单一杠杆驱动"哲学；军港需求减半（537→268 座）但仍有意义，不摧毁军港价值。备选 +5%/级（×1.5，杯水车薪）与 +20%/级（×3，军港价值骤降、倍率远超军械科技）均被否决。
5. **UI（Q4=A）**：军事面板展示虫洞容量加成来源——军力容量行/兵营军港卡将「虫洞 LvX 军力容量 +Y%」与军械科技容量行并列（沿用现有 `productionReport` 的 `capNote` 展示模式）；虫洞建筑卡描述追加军力线效果文本。
6. **周目语义**：沿用 ADR-0042——虫洞随 NG+ 重置，容量加成不进遗产（`permanentBonuses.militaryCap` 仅来自攻占奖励）。零迁移、不升 SCHEMA。

## 为什么

- **机制二分不破**：乘数挂在等级维度建筑上，数量流（军港）与乘数流（永久/声望/军械/虫洞）结构不变，只是乘数流多一轴。
- **单一杠杆**：军力容量成长完全由虫洞等级驱动，与探索线四效果共用同一根杠杆，无科技+建筑双杠杆失控风险。
- **与消耗锚定自洽**：不引入豁免规则，`cap×2%`/胁迫门槛百分比语义不动；封顶后的溢出容量天然成为"军力深度"释放（攒更多、派更多），无需新不变量。
- **对称性**：与军械科技同为独立乘法因子（`×(1+0.1×军械) × (1+0.1×虫洞)`），叠加语义清晰、可测。

## 后果

- **引擎**：`balance.ts` 新增根因子 `WORMHOLE_CAP_PER_LEVEL = 0.1`；`production.ts` 的 `militaryCap` 公式追加因子（读 `state.upgrades.wormhole ?? 0`，不引 exploration 防环依赖——与 `generate.ts` 读 wormhole 的方式一致）。
- **UI**：军力容量展示（`productionReport` 的 `capNote` 或军事区容量行）含虫洞加成来源；虫洞建筑卡描述追加军力线；i18n 中/英新增 key。
- **测试**：`production.test.ts` / `balance-simulation.test.ts` 等含 `militaryCap` 断言的用例追加虫洞因子为 0 时的兼容（无虫洞时与现状逐字节一致）；新增虫洞等级作用断言（Lv0 无变化、Lv10 ×2）。
- **平衡**：虫洞满级时军港需求减半，但军港仍是必要数量流；自动攻占/探索派遣可投注上限提升，与守卫锚产出不冲突（守卫不受容量乘数影响，只是"能投入"的池子变大）。
- **关联**：↔ ADR-0042（虫洞探索线 → 本 ADR 追加军力线）；↔ ADR-0036（机制二分——本决策不引入数量×等级耦合）；↔ ADR-0027（军械科技容量轴 → 虫洞成为第二条容量轴）；↔ ADR-0028（同源锚定——守卫锚产出不受影响，无漂移）。
