# 平衡模拟方法论：一次性脚本跑完即删 + 不变量测试钉死

数值调参流程固定为：**先写临时平衡模拟脚本（`scripts/balance-sim.ts`，跑完即删，不入库）** 做确定性模拟（贪心「最短等待优先」/固定 seed 场景），校准目标（通关节奏 ±30% 内、决策均衡点、高周目不塌缩/不印钞），校准结论回写 spec 与 `balance.ts` 注释；**数学性质用仓库内不变量测试钉死**（ROI≡P、成本单调、对称增长等），防止未来调参悄悄破坏。

**状态**: Accepted（2026-08-06 起为数值决策标准流程）
**证据**: `.scratch/balance-rework/spec.md`（Q7 决策）、`.scratch/post100-cost-curve/spec.md`（ticket 03 校准）、`.scratch/interstellar-buildings/spec.md`（Further Notes 校准结论）；commit `24df123`（firstBuild 奖励 500→50 定标）

## 背景

数值平衡单靠手调 + 直觉不可靠：balance-rework 用截图实测（升级/买入 ROI 比最高 15166×）暴露公式病，post100 需要验证「高 NG+ ×64/×1024 不塌缩」，interstellar 需要验证「满级 1-2 周可达 + 能源闭环自洽」。这些都需要可复现的数值实验，但实验脚本是临时的，不该污染仓库。

## 决策

1. **一次性脚本**：`scripts/balance-sim.ts` 每次调参临时编写、跑完即删；确定性模拟（注入固定 seed、贪心策略、保守口径），校准结论回写 spec「Further Notes」与 balance.ts 常量注释（含日期）。
2. **校准目标明确化**：每次模拟先列硬约束（如通关节奏 ±30%、满级 1-2 周、维护费占比 ≤5%、相对价格跨周目同阶），四类目标：① 节奏（到达解锁阈值时间）② 决策均衡（买/升/攻/守都有价值）③ 高周目不塌缩（相对价格/印钞）④ 闭环自洽（能源/资源链）。
3. **不变量测试常驻**：数学性质进仓库测试（`ROI≡P`、成本随 count 单调不降、unique 对称 ×2/×2 恒定、post100 阈值点跳变）——模拟验证「当前参数」，不变量保证「未来参数不破坏性质」。
4. **校准即定稿**：模拟通过 → 常量定稿并注释「balance-sim 校准」；未通过 → 调整常量重跑，不靠感觉拍数字。

## 为什么

- 挂机游戏数值是「指数/幂律世界」，直觉在千亿级产出下完全失效（post100 背景：升级成本 0.00-0.07 秒产出）；模拟是唯一可信的调参手段。
- 脚本跑完即删保持仓库干净（`scripts/` 只留可复用工具），同时校准结论以注释形式留痕——「为什么是这个数」比「数是多少」更值钱。
- 不变量测试是模拟与常驻测试的分工：模拟回答「这组参数现在好不好」，不变量回答「这组参数以后会不会被改坏」。

## 后果

- 每个新数值域（胁迫外交、舰队、无尽生成目标）的常量注释都标注「初稿待 balance-sim 校准」或「sim 校准定稿」——数值成熟度可审计。
- 修改已定稿数值必须先跑模拟 + 更新不变量断言，否则 code-review 打回（过程纪律）。
- 模拟脚本是一次性资产，但**校准报告**是持久资产——结论写进 spec 与 ADR，脚本删除不丢知识。
