# 卡片化改造：建造/科技/外交/军事/成就/探索交互组件同构

UI 从「列表行」演进为「卡片网格」：建造面板卡片化（分区折叠 + 锁定原因 + 图标 + 升级高亮）、科技/外交/军事/探索交互组件与建造物**同构**（同一卡片语法）、档案成就卡牌化（图标资产 + progress 读数 + 网格）。外交派系卡与攻占卡多列网格化，移动端 ≤480px 两列。

**状态**: Accepted
**日期**: 2026-08-07
**证据**: commit `405afee`（成就数据卡片化）、`9878a79`（档案面板成就卡牌化）、`2b17cd7`（外交/攻占多列网格）、`3d43fa5`（科技/外交/军事/探索交互组件卡片化同构）、`df76aaf`（移动端紧凑布局）；`.scratch/building-cards/spec.md`

## 背景

早期 UI 是文本行列表（终端风格），建造面板随建筑数量增长后信息密度不足：无图标、无产出对比、锁定原因不可见；科技/外交/军事等交互区各自为政，样式与交互不一致（军事面板科技区曾误混入科技面板，commit `7a1d0fa` 修复）。

## 决策

1. **卡片统一语法**：建造物卡片承载「图标 + 名称 + 数量/等级 + 产出 + 成本 + 相对价格 + 按钮」，锁定卡折叠显示解锁条件。
2. **交互组件同构**：科技/外交/军事/探索交互组件复用同一卡片结构（`data-card` 家族契约）——一致性降低认知成本，也让 E2E 断言统一。
3. **成就卡牌化**：档案页成就网格（`ach-card`），图标资产 + 进度读数（progress 谓词同源引用，防数值漂移——成就条件与引擎判定共用同一函数，见 endlessIIUnlocked 先例）。
4. **响应式网格**：多列网格 + ≤480px 两列断点（`d7511d4`），单拇指操作目标尺寸。

## 为什么

- 卡片化提升信息密度与可扫读性——挂机玩家高频查看建造面板，产出/成本/相对价格的并排呈现是决策必需品。
- 交互组件同构的收益是**样式与断言单一**：卡片语法统一后，新玩法入口（探索/军事）无需重新设计交互范式。
- 成就进度「谓词同源」延续「成就条件 = 引擎判定函数」的单真源原则（与 AGENTS.md 的 `data-*` 语义化同精神）：显示与逻辑永不脱节。

## 后果

- 卡片化与 250ms 全量重建（ADR-0014）配合良好：卡片是纯渲染结构，升级高亮用一次性窗口类。
- 网格化后 DOM 结构更规整，E2E 的 `data-*` 断言（ADR-0020）可精确定位卡片内元素。
- 移动端布局约束（44px 触控目标、两列断点）成为后续所有卡片组件的最低标准。
