# 声望加成扩展：探索槽位 + 护航费折扣（探索模块接入声望阶梯）

声望阶梯表（`REPUTATION_TIERS`，0-100 五档、累积生效）扩展两列探索加成——探索槽位（80 档 +1、100 档 +2）与护航费折扣（80 档 −5%、100 档 −10%），探索模块（原无声望加成）由此接入声望系统。加成全部落在「上限/效率」类：槽位是并行探索上限（上限同步 +2 → 22，防声望项被 min 吞掉），护航费折扣是消耗侧效率（与 warpDrive Lv20 −10% 同通道叠加，clamp ≥ 0）——均不触碰每秒产出系数，延续 `reputation.ts` 的铁律边界。数值为实现期平衡模拟定标，非终值。

**状态**: Accepted
**日期**: 2026-08-14
**证据**: `src/engine/reputation.ts`（REPUTATION_TIERS）；`src/engine/exploration.ts:143-149`（explorationSlots）、`:228-229`（escortFee）

## 背景

声望跨周目累计（ADR-0009 修订，2026-08-14）后，新周目开局即可能满声望（100）——阶梯加成成为成就系统的永久回报，需要更多「声望价值」落点。军事模块已有两处（军力上限 +0.2、攻占成功率 +0.15），探索模块完全没吃到声望；而探索恰是 NG+ 后的主力长线玩法（枢纽/虫洞/护航三线），声望加成落探索最贴合「周目越深探索越强」的主线。

## 决策

1. **阶梯表扩展**：`ReputationBonuses` 接口与 `REPUTATION_TIERS` 增 `exploreSlotBonus`（80→+1、100→+2）与 `escortFeeDiscount`（80→0.05、100→0.10）两列，档位累积语义与现状一致（取当前声望命中的最高档）。
2. **槽位消费**：`explorationSlots` 公式由 `min(20, 5 + 枢纽 + 虫洞)` 改为 `min(20 + 声望槽, 5 + 枢纽 + 虫洞 + 声望槽)`——上限同步提升，否则枢纽/虫洞终局皆满后声望项被 min 吞掉、加成无效。满配：基础 5 + 枢纽 5 + 虫洞 10 + 声望 2 = 22。
3. **护航费消费**：`escortFee` 折扣通道与 warpDrive 叠加——`× (1 − WARP_ESCORT_FEE_REDUCTION − escortFeeDiscount)`，clamp 下限 0（满配 −10% −10% = −20%）。
4. **铁律保持**：不触碰每秒产出系数——探索收获倍率、天体产出增益上限（+50% cap）、护航收获倍率（ADR-0054 同杠杆）均不动。

## 为什么

- 探索槽（并行能力，上限类）与护航费（消耗效率，效率类）是铁律边界内最直观、最贴合探索玩法的两个落点；军事保持现状（已有两处），不加战力直乘（战力是能力而非上限，会推高守卫，破坏平衡面）。
- 否决直接加探索产出倍率：违反「永不触碰每秒产出系数」铁律。
- 否决探索时长缩短：改动出发时固化的时长契约（ADR-0008），影响面大于收益。
- 否决探索槽单独提上限到 22 之外的数值：槽位是终局资源，+2 已是阶梯两档的温和增益。

## 后果

- 数值（+2 槽、−10% 护航费）为建议值，实现期须经平衡模拟定标（`balance-simulation.test.ts` 护航模拟可加断言）。
- 探索页 UI 的槽位锁定提示（`jumpgateLevelForSlot`/`wormholeLevelForSlot` 数据驱动）对声望槽不适用——声望槽由声望而非建筑等级解锁，提示文案需单独处理（或归入「探索页信息架构」后续）。
- 设置页/档案页声望卡可展示探索加成来源（阶梯档位），属 UI 展示细节，不阻塞引擎落地。
