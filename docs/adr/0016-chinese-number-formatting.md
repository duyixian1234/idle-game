# 中文大数字缩写 + 相对价格显示（formatNumber / timeToSave）

数值展示用**中文四级单位缩写**（万/亿/兆/京/垓/秭/穰/沟/涧/正/载，每 4 位十进制一级），`formatNumber(n)` 统一入口：< 10000 保留千分位 + 两位小数，≥ 10000 转中文单位 + 两位小数；四舍五入采用 half-away-from-zero + 1e-9 容差（防 1.005 这类十进制二进制表示误差）。成本显示附带**相对价格**：`timeToSave(cost, production)` 计算「攒多久产出」的瓶颈资源口径，`formatTimeToSave` 转「≈N 秒/分钟/小时产出」文案。

**状态**: Accepted
**日期**: 2026-08-05（大数字缩写，spec ticket 04）~ 2026-08-07（相对价格，cost-softcap ticket 02）
**证据**: `src/engine/format.ts` 全文件；`.scratch/cost-softcap/spec.md`（Q10 相对价格显示）；commit `734015e`（04 大数字缩写与离线收益）

## 背景

挂机数值可达千亿级（用户实测 7000 亿/s），裸数字不可读；英文缩写（1.2K/3.4M）不符合中文习惯。同时后期「成本 vs 产出」的决策需要可比口径——绝对数字在产出膨胀后失去直觉（100 亿对 7000 亿/s 的玩家毫无意义，见 ADR-0022 背景）。

## 决策

1. **中文四级单位**：`BIG_UNITS = ['', '万', '亿', '兆', '京', '垓', '秭', '穰', '沟', '涧', '正', '载']`——每 4 位一级，与中文数字习惯一致；进位前先舍入（999999.995 → 100.00万 而非 99.99万）。
2. **两位小数定式**：`formatNumber(1) === '1.00'`（用户约定，测试锁定）——所有 UI 数值统一两位小数，格式永不漂移。
3. **half-away-from-zero**：`roundHalfAwayFromZero` + `ROUNDING_EPSILON = 1e-9`——IEEE-754 二进制表示的十进制进位问题（1.005）用固定 epsilon 拉回期望侧。
4. **相对价格显示**：`timeToSave` 按瓶颈资源口径（`max(成本ᵢ/产出ᵢ)`，只统计成本 > 0 且有正产出的项），无有效项返回 null（占位）；`formatTimeToSave` 向上取整防「0 秒」误导。
5. **格式化器家族**：`formatRate`（+/秒）、`formatPercent`、`formatMultiplier`（倍）、`formatPlayTime`（通关时长）统一经 formatNumber 派生。

## 为什么

- 中文单位 + 两位小数是「读数爽感」的实现载体（主 spec User Story 7），同时是用户明确约定的格式契约（`formatNumber(1) === '1.00'`）。
- 相对价格把「成本决策」从绝对数字转为时间直觉——「≈5 分钟产出」比「3.15 亿」对挂机玩家更有决策价值，且跨周目（×64/×1024）自动可比。
- 舍入策略半离家（ties away from zero）是刻意选择：挂机展示场景「少显示一分」比「多显示一分」更易让玩家误判负担。

## 后果

- 所有 UI 数值一律走 format 家族，禁止裸 `toString()`（代码评审纪律）。
- `timeToSave` 的瓶颈口径与 post100 动态下限（ADR-0022）同源（都锚定 netProduction），相对价格行在成本曲线变化时自动反映摩擦。
- 展示层舍入（两位小数）与引擎层计算（浮点原值）严格分离——UI 永远显示 `formatNumber` 结果，引擎永远用原始数。
