# 档案绑定固定随机种子：分域计数器 + mulberry32（防 SL / 跨设备延续）

随机性由档案绑定：存档 v5 新增 `seed`（32 位种子，新建档生成、跨周目不变）与 `rngCounters`（分域调用计数器，随自动保存写入）；引擎自实现 **mulberry32**（约 128 字节，零外部依赖），`roll(state, domain) = mulberry32((seed ^ SALT[domain] ^ counter[domain]) >>> 0)()`，每次 roll 后计数器 +1 写回。结果型随机走持久化计数器，装饰型随机（文案/间隔抖动）走 seed 派生即时流（可复现但不持久化）。

**状态**: Accepted
**日期**: 2026-08-06（fixed-rng 定稿，grill 三轮 21 决策）
**证据**: `src/engine/rng.ts` 全文件；`.scratch/fixed-rng/spec.md`；commit `9d8cd93` 附近（v5 迁移）

## 背景

两个玩家可感知缺陷：① **SL 漏洞**——tick 250ms 跑一次，攻占成功率与事件类型都在 tick 内 roll，自动存档是节流 + beforeunload（间歇性）；刷新页面 = 内存态从存档恢复但 `Math.random` 状态重置 → 「读档重抽」：攻占倒计时最后几秒反复刷新免费重抽成功率。② **跨设备不一致**——导出存档到另一设备，随机序列无法从保存点延续（随机状态不在存档里）。

## 决策

1. **seed 跨周目保留**：`startNewGamePlus` 不重置 seed 与 rngCounters——同一档案 = 同一随机宇宙的轮回，counter 保留使每周目序列延续推进（若重置，每周目第 1 次 roll 与上周目相同）。
2. **分域隔离**：`RngDomain = 'event' | 'conquest' | 'explore' | 'generate' | 'duration'`，每域独立计数器 + 固定盐（SALT），防跨域序列相关。
3. **分层随机**：结果型（事件类型/攻占成功率/探索结果/时长）走持久化计数器；装饰型（事件文案/间隔抖动）走 `streamFor` 即时流——不占持久化字段。
4. **签名兼容**：所有函数签名保持 `rng?: () => number` 可选——**显式传入 = 测试注入（跳过计数器），不传 = 生产模式走持久域**。main.ts 零改动。
5. **不设对抗式防御**：seed/counter 存于玩家可编辑存档 JSON，玩家手动改存档作弊是挂机单机游戏的固有自由，spec 明确不防。

## 为什么

- 威胁模型是「250ms tick + 节流存档 + 页面重建重置 Math.random」——固定种子 + 持久计数器使「刷新重抽」变为「刷新后序列继续」，SL 收益归零，无需禁止刷新/限流。
- 分域计数器的价值在于可精确重放：给定 (seed, domain, counter) 可重放任意一次 roll，测试与回放皆可。
- 装饰型随机不持久化，避免存档字段随每次文案随机膨胀。

## 后果

- 存档 v5 迁移陷阱（migrateV3ToV4 必须写死 SCHEMA_V4）成为链式迁移的经典坑点（ADR-0005）。
- 探索系统沿用同一机制：**结果出发时固化**（ADR-0008）——随机序列与结果落盘解耦，两层防 SL。
- 时间型随机（Date.now() 驱动的解锁时刻/时间戳）明确不在种子管辖范围——种子只管结果型随机，不管时间轴。
