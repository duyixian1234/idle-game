# 250ms 全量重建渲染模型 + 会话 UI 态不进存档 + 差值角标

渲染模型是**250ms 一拍的全量重建**：`main.ts` 的 `loop()` 每 250ms 执行 `tick(state, Date.now())` 后 `session.render()` 用 innerHTML 重建全部面板内容；跨重建记忆的 UI 状态（折叠展开/角标快照/弹窗开关/typewriter 进度/升级高亮/日志方向）集中为**会话 UI 态**（`SessionUiState`，内存态，不进存档）；事件/成就/日志角标用**差值派生**（当前存量 − seen 快照，读即已读），零动画。

**状态**: Accepted
**日期**: 2026-08-06（ui-restructure 定稿）~ 2026-08-07（session 收编）
**证据**: `src/main.ts:92-104`（loop）；`src/ui/session/index.ts:77-111`（SessionUiState 16 态）；`.scratch/ui-restructure/spec.md`

## 背景

挂机游戏主循环天然是「时间推进 + 状态刷新」：250ms tick 是最低成本的时间分辨率。全量重建（innerHTML 覆盖）比增量 diff 简单得多，但代价是——**任何跨拍状态都必须有外部存储**（DOM 每次被重建，DOM 属性即会话记忆，但会丢）。曾两次踩 hover 动画坑（闪烁振荡、transition 重放），教训是动画不能依赖重建重放。

## 决策

1. **全量重建 + 会话态**：render 每拍重建面板内容；折叠展开、角标快照、弹窗开关、typewriter 进度、升级高亮、日志方向、买满待执行动作等 16 项会话 UI 态集中在 `SessionUiState`（session/index.ts 内闭包，监听器共享），**不进存档**。
2. **重操作换引用**：导入/导出/重置/NG+ 等替换 `GameState` 引用的动作，通过 `setState(next)` 换引用 + 重建——不原地改 state。
3. **角标差值派生**：`max(0, 当前存量 − seenSnapshot)`，进入对应页时快照（读即已读）；99+ 封顶；纯函数派生无动画，规避 250ms 重建 + transition 坑。
4. **升级高亮一次性**：`justUpgradedId/Until` 1.2s 窗口，窗口内重建只重放首帧，过期自动消失。
5. **持久化偏好走 localStorage**（二级 tab 选择、日志方向），与存档（玩法状态）分离——设置去中心化后日志方向迁日志页头部、天体显隐迁探索页（commit `6ba7e4d`）。

## 为什么

- 全量重建的简单性远大于 diff 的性能收益——DOM 规模小（<200 节点），250ms 重建毫无压力，却换来「render 函数无状态纯映射」的可测性。
- 会话态与存档严格分离是双赢：存档字段不被 UI 噪音污染（ADR-0005 的可选字段先例只管用户偏好），UI 态刷新即重置（挂机刷新常态，存量重报是噪音）。
- 差值角标「读即已读」语义（刷新不重报存量）对挂机场景是刻意设计——角标是「新东西」信号，不是「总量」指示器。

## 后果

- 任何交互若要跨重建记忆，必须登记进 `SessionUiState` 或 localStorage——DOM 属性不可作为会话存储（会被下一拍重建抹掉）。
- render 函数保持纯映射，UI 冒烟测试可直接断言「给定 state → 渲染结构」（ADR-0017）。
- 代价：全量重建使「局部动画/过渡」受限，所有视觉反馈须一次性（高亮窗口）或 CSS 级（不依赖重建重放）。
