# 永恒殖民（endlessII）成就解锁条件重设计

**Status:** implemented（3 ticket 全部 resolved，2026-08-06；447 vitest + typecheck + build 全绿，E2E 用户手动验证通过）

## Problem Statement

「永恒殖民」（endlessII）与「深空碑文」（deepSpace）两个成就是死代码：条件谓词读取 `storyFlags.endlessII` / `storyFlags.deepSpace`，但 `storyFlags` 的唯一赋值路径 `playMilestone` 的 11 处调用点（engine 6 / diplomacy 3 / conquest 2）中**不存在这两个 key**，也无任何旁路（事件/探索/存档迁移）赋值——正常游戏流程永远无法达成，图鉴中永久灰置。

用户为「永恒殖民」提案解锁条件「累计游玩 3 小时 + 产出 100 亿矿产」。经数值核算（引擎源码口径）：满配后期净攒约 4~9 亿/小时，100 亿 ≈ 40~60 在线小时——「3 小时」在 AND 逻辑下纯装饰，实际约束只有 100 亿这一个（产出 = 速率 × 时间，且速率随成长递增，AND 组合几乎总由量级大的条件单方面生效）。同时需要修复死代码根因（挂点缺失）。

## Solution

玩家在进入无限模式（统一联邦达成）后继续殖民，本局累计采集达到 100 亿矿物时，自动解锁「永恒殖民」成就：播放终局口吻的叙事里程碑《百亿之年》、获得 5,000,000 矿物一次性奖励与 8 点声望、图鉴永久点亮。时间意象由文案承载（判定层只保留 100 亿单一硬约束），避免装饰性条件误导。

「深空碑文」本次不动（见 Out of Scope）。

## User Stories

1. 作为通关玩家，我希望进入无限模式后继续游玩，以便在本局累计采集达到 100 亿矿物时解锁「永恒殖民」。
2. 作为玩家，我希望该成就要求已进入无限模式，以便叙事顺序正确（先「无限启程」、后「永恒殖民」，杜绝第一周目通关前提前触发）。
3. 作为玩家，我希望达成判定只用「100 亿累计采集」这一条硬约束，以便不被装饰性的时间条件误导（「我 3 小时到了为什么没达成」）。
4. 作为玩家，我希望解锁瞬间看到终局口吻的叙事文本，以便与「旅程才刚刚开始」的起点语气区分，形成旅程回顾的里程碑感。
5. 作为玩家，我希望获得与门槛匹配的一次性奖励（5,000,000 矿物），以便 100 亿难度的回报不再寒酸（原 10 万 ≈ 产出的 0.0001%）。
6. 作为玩家，我希望声望 +8，以便终局成就的声望梯度与同量级成就（星海之王 10 亿矿物 / rep 8）一致。
7. 作为玩家，我希望该成就在 NG+ 后不重复解锁，以便叙事成就保持一次性语义（架构注释：story 类可重解锁会导致二周目开局白拿全部叙事成就）。
8. 作为玩家，我希望条件谓词用现有统计字段派生，以便无需新增统计计数、回溯与周目语义天然正确。
9. 作为测试者，我希望成就解锁（checkAchievements）与叙事播报（playMilestone）可独立验证，以便复用既有引擎测试 seam。
10. 作为维护者，我希望挂点条件与成就谓词同源（共享判定），以便两处数值不会漂移。

## Implementation Decisions

- **条件谓词**（纯 state 派生、零新增字段、与既有成就谓词同构）：
  - 前置：已进入无限模式（统一联邦达成时置位，跨周目保留）
  - 门槛：本局累计采集矿物 ≥ 100 亿（周目内口径，NG+ 归零；与 `mineral1B` 同款字段）
  - **时间条件不入判定**——数值核算证明 3h 不构成约束；时间意象由 desc / 叙事文本承载
- **类别**：保持 `story`（永久解锁、跨周目保留、不可重解锁；与「storyFlags 驱动不可重解锁，防二周目白拿」的既有架构一致）
- **奖励**：一次性矿物 100,000 → 5,000,000；声望 5 → 8（对标 `mineral1B`：10 亿/50 万/rep 8，难度 10 倍、奖励 10 倍）
- **叙事接线**：tick 主循环在既有成就检查点附近追加叙事挂点，条件满足即播放「永恒殖民」里程碑文本；成就解锁由既有 `checkAchievements` 自然处理（谓词变化即生效，不建平行机制）
- **挂点与谓词同源**：提取共享判定（成就条件与叙事挂点引用同一谓词），避免两处数值漂移
- **文案**（实现期可微调）：里程碑文本改写为终局口吻——《百亿之年》：回顾「石头变城市、荒芜变星海」+ 百亿意象 + 「这不是终点，是下一百亿的起点」收束；成就 desc 更新为「累计采集 100 亿矿物。把石头变成城市，把荒芜变成星海——日志仍在书写。」
- **无存档变更**：纯谓词 + 挂点改动，schemaVersion 不升，旧档无需迁移

## Testing Decisions

- 引擎层为主 seam（纯 TS Vitest，既有先例）：
  - 成就解锁：`checkAchievements` 模式（achievements.test.ts 先例）——前置拦截、门槛边界（99.99 亿不触发 / 100 亿触发）、奖励与 rep、story 类一次性语义
  - 叙事播报：`playMilestone` 模式（story.test.ts 先例）——挂点触发、防重复（storyFlags 已置则跳过）
- 边界用例：未进无限模式即使 100 亿也不触发；NG+ 后不重解锁
- UI 层零改动（成就日志经既有 pushLog 管道）；E2E 不新增（纯引擎行为 + 日志播报，smoke 覆盖即可）
- 回归：全量 vitest + typecheck + build

## Out of Scope

- 「深空碑文」（deepSpace）挂点修复——同属死代码审计发现，另立问题
- 存档版本升级（无 schema 变化）
- NG+ / 无限模式数值平衡调整
- 成就 desc 与叙事文本的进一步润色（实现期可微调文案，不动判定）

## Further Notes

- 数值基线（子代理核算，引擎源码口径）：满配后期净攒约 4~9 亿/h；从 0 攒 100 亿 ≈ 40~60 在线小时（成长爬坡 25~40h + 满配冲刺 12~20h）；NG+ permanentMult（1 + 0.15×周目）同比加速（10 周目满配 ~10~20 亿/h）
- 梯度确认：`mineral1B`（星海之王，10 亿）→ 本成就（100 亿）10 倍落差
- 审计结论：`storyFlags` 唯一赋值路径为 `playMilestone`（story.ts），其 11 处调用点无 `deepSpace` / `endlessII` → 死代码根因；`MILESTONE_STORIES` 文案与成就定义均已就绪，仅挂点未接线
- 实现记录（2026-08-06）：共享判定 `endlessIIUnlocked` 导出自 achievements.ts（成就谓词与 tick 挂点同源引用，防数值漂移）；tick 挂点位于 checkEnding 之后、checkAchievements 之前（叙事先于成就播报）；`playMilestone(state, 'endlessII')` 内部 storyFlags 防重复；文本《百亿之年》已改写。叙事测试走 `tick` 集成路径（未进无限不播放 / 满足即播且仅一次 / 成就同步解锁）。
