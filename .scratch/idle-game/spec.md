# Spec: 文本式挂机游戏（太空采矿）

## Problem Statement

用户想要一个用网页技术实现的文本式挂机游戏：太空采矿/殖民题材、叙事驱动解锁、完整可玩（约 3-5 小时流程）、自用并可与朋友分享。现有工具链是 TypeScript + Vite（pnpm 管理依赖），游戏需可离线挂机、有明确的通关目标与通关后内容。

## Solution

一个纯前端的静态单页游戏。玩家从一颗荒芜星球起步，建造建筑产出矿物/能源/科技点三种资源，研发科技解锁新能力，通过叙事事件逐步解锁 5 颗星球（每颗引入一个新机制）；4 个派系的好感度与外交行动（贸易/结盟/威慑）推动终局——星系统一联邦。通关后开放无限模式与 NG+（部分继承）。IndexedDB 自动存档 + JSON 导出/导入，离线收益按真实时间差结算（8 小时封顶）。界面为终端文本风 + 轻量 UI（顶部资源条 + 中央日志流 + 操作面板），响应式适配移动端，WebAudio 合成轻音效可静音。

## User Stories

1. 作为一名玩家，我希望首次打开游戏时看到轻量引导（3-5 步），以便知道第一步该做什么。
2. 作为一名玩家，我希望在荒芜星球上建造第一个建筑（采矿机），以便开始产出矿物。
3. 作为一名玩家，我希望顶部资源条实时显示矿物/能源/科技点，以便随时掌握家底。
4. 作为一名玩家，我希望矿物能自动累积，以便离线也能成长（挂机核心）。
5. 作为一名玩家，我希望购买/升级建筑能提升资源产出效率，以便数值有成长曲线。
6. 作为一名玩家，我希望研发科技能解锁新建筑与加成，以便有第二个升级维度（双升级线）。
7. 作为一名玩家，我希望看到大数字以中文单位缩写（万/亿/兆/京…）显示，以便读数和爽感。
8. 作为一名玩家，我希望满足条件后解锁下一颗星球，以便叙事驱动持续推进。
9. 作为一名玩家，我希望每颗新星球带来一种新机制，以便玩法不断有新鲜感。
10. 作为一名玩家，我希望随机事件（贸易商/陨石雨/虫族警报）在日志中触发，以便挂机过程有变化与惊喜。
11. 作为一名玩家，我希望遇到 4 个派系并了解它们的好感度，以便有明确的外交目标。
12. 作为一名玩家，我希望对派系执行贸易/结盟/威慑行动，以便影响好感度推进统一进程。
13. 作为一名玩家，我希望达成"星系统一联邦"结局（全派系好感达标或结盟），以便有完整的通关闭环。
14. 作为一名玩家，我希望通关后进入无限模式继续挂机，以便不浪费既有进度。
15. 作为一名玩家，我希望可开启 NG+ 携带科技点/派系图鉴/永久加成重开，以便二周目更快更有目标。
16. 作为一名玩家，我希望关闭页面后回归时看到离线收益结算报告（8 小时封顶），以便感知挂机价值。
17. 作为一名玩家，我希望游戏自动保存到本地，以便无需手动存档。
18. 作为一名玩家，我希望将存档导出为 JSON 文件，以便分享给朋友。
19. 作为一名玩家，我希望导入朋友分享的存档 JSON，以便继承对方进度。
20. 作为一名玩家，我希望有一键静音开关，以便安静挂机。
21. 作为一名玩家，我希望在手机上打开页面也能正常游玩（响应式），以便随时查看进度。
22. 作为一名玩家，我希望剧情文本量充实（全游戏约 3000-5000 字），以便叙事有代入感而非点缀。
23. 作为一名玩家，我希望新游戏进度可通过删除存档/重置来重新开始，以便随时体验不同策略。

## Implementation Decisions

- **技术栈**：TypeScript + Vite，pnpm 管理依赖，构建产物为静态站点。无后端。
- **分层架构**：三层——纯 TS 游戏引擎层（资源/建筑/科技/事件/外交/离线结算/存档序列化，零 DOM 依赖）、UI 渲染层（DOM，只做状态到界面的映射，不承载业务逻辑）、持久化层（IndexedDB 自动保存，节流触发）。
- **引擎-UI 通信**：引擎产出不可变状态快照，UI 订阅快照渲染；用户操作经 action 函数进入引擎，不直接改 UI 状态。这保证引擎可脱离 DOM 测试。
- **数值系统**：三种资源（矿物/能源/科技点），产出受建筑数量 × 科技系数影响；大数字中文单位缩写（万/亿/兆/京/垓…）。
- **离线收益**：基于存档内时间戳与当前真实时间的差值计算产出，封顶 8 小时；回归时生成结算日志。
- **叙事结构**：5 星球解锁树，按资源/科技阈值顺序解锁；每星球一个独特机制（具体机制在实现阶段出设计提案供确认）；充实型剧情 3000-5000 字。
- **外交系统**：4 个派系，各有好感度数值；贸易/结盟/威慑三类行动，效果受资源与既有关系影响；统一联邦 = 全部派系好感达标或已结盟。
- **随机事件**：轻量概率触发（计时器 + 事件表），不影响主线推进。
- **通关后**：结局达成 → 解锁无限模式（数值继续膨胀 + 事件更密）；NG+ 部分继承（科技点/派系图鉴/永久加成），资源与建筑重置。
- **存档格式**：版本化 JSON（含 schema version 字段），字段为引擎状态全量快照；导出/导入即该 JSON 文件。
- **音效**：WebAudio 合成短音效（点击/升级/事件/结局），偏好设置存于 localStorage 或存档内，一键静音。
- **界面**：终端/日志文本流为主体，顶部资源条 + 中央日志 + 操作面板（建筑/科技/外交分面板）；响应式断点适配窄屏。
- **新手引导**：状态机式 3-5 步引导，引导进度随存档持久化。

## Testing Decisions

- **测试分两层 seam**（引擎层为主 seam，UI 冒烟为次 seam）：
  1. 引擎层（Vitest 单元测试）：覆盖资源产出计算、建筑/科技购买、解锁条件判定、外交好感度变化、随机事件触发、离线结算、存档序列化往返。核心原则：只测外部行为（给定状态与 action → 断言新状态），不测实现细节；离线结算用可控时钟（注入时间源）做确定性断言。
  2. UI 层（Vitest + jsdom 冒烟）：渲染初始状态、资源条更新、点击操作后引擎状态变化反映到界面、静音开关、导入/导出按钮可用性。
- **好测试的标准**：给定输入状态 + action，断言输出状态/渲染结果，不 mock 内部方法、不依赖 DOM 实现细节。
- **待测模块**：engine（resources/buildings/tech/events/diplomacy/offline/save）、ui（render/smoke）。
- **先例**：本仓库为全新项目，无既有测试；本 spec 建立第一批测试范式，后续模块沿用同一 seam。

## Out of Scope

- 后端、账号系统、云存档、排行榜（目标为自用 + 分享朋友，本地存档 + JSON 文件分享）。
- 上线级运营能力（埋点、公告、版本热更）。
- 多语言（仅中文）。
- 复杂美术与动画（纯文本 + 轻量 UI；音效为 WebAudio 合成，无外部音频资源）。
- 移动端原生打包（仅响应式网页）。

## Further Notes

- 分发方式：构建后部署到免费静态托管（CloudStudio/EdgeOne Pages），生成链接分享；用户可在设置中随时删除。
- 星球机制与事件/剧情具体文案在实现阶段产出设计提案，供用户确认后落地。
- 通关时长目标约 3-5 小时（现实挂机时间，非活跃游玩时间）。
- 依赖本 spec 的工程技能读取入口：`.scratch/` 目录约定见 `docs/agents/issue-tracker.md`；域词汇约定（CONTEXT.md 不存在时静默）见 `docs/agents/domain.md`。
