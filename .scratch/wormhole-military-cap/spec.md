# 虫洞军力线：军力容量随虫洞等级放大（每级 +10%，Lv10 ×2）

**Status:** ready-for-agent

**Parent:** 无（独立 feature spec）

## Problem Statement

后期（infinite 阶段）军事与探索行动对军力需求持续膨胀，但军力容量供给脱节：

1. **容量是硬瓶颈**：`militaryCap` 的数量流只有军港（200/座线性），唯一等级放大轴军械科技止步 Lv5（×1.5）。满 20 槽并行探索需 ≈210k 军力（纯靠军港需 ≈537 座）；自动攻占 60s 投注、raid 击退防御均受容量限制。
2. **探索成本锚定容量**：单槽军力 = `cap×2%`（clamp 40~1000），容量不足直接卡死多槽并行派遣。
3. **虫洞是 infinite 深水区建筑**（结盟 ≥10 仅 infinite 可达、成本兆级），与军力需求爆发时点重合，但现有效果全部指向探索线，不含军力容量。

## Solution

给虫洞追加第二条效果线：**军力容量随虫洞等级放大**——`militaryCap` 公式追加独立乘法因子 `(1 + 0.1×虫洞等级)`，Lv10 时军力容量翻倍（×2）。虫洞与军械科技并列成为军力容量的第二等级放大轴。

- 机制落点：全局军力容量乘数（ADR-0047）。不采用「每座兵营容量贡献」或「军港容量乘数」——那两种引入「数量×等级」耦合，违反 ADR-0036 机制二分。
- 范围：只放大容量，不碰军力产出（兵营 0.5/s 不动）——攻占守卫锚定产出，放大产出会让守卫/raid 消耗同步膨胀，与目标相悖。
- 消耗锚定：接受探索单槽军力、勒索/臣服门槛随容量等比例放大（`cost-anchors-cap` 不变量）；探索军力成本 cap≥50,000 后已封顶 1000/槽，封顶后的虫洞容量是纯释放。
- 周目语义：虫洞随 NG+ 重置（ADR-0042 既有），容量加成不进遗产，零迁移、不升 SCHEMA。

## User Stories

1. 作为中期玩家，我在解锁虫洞后能看到「军力容量」在无军港新增的情况下随虫洞升级增长，以便为探索派遣和自动攻占蓄力。
2. 作为 infinite 阶段玩家，我拥有 Lv10 虫洞时军力容量翻倍（×2），以便仅用一半军港即可维持满 20 槽并行探索的军力需求。
3. 作为军事玩家，我希望军力容量乘数来自等级维度建筑（虫洞）而非军港数量，以便在新周目重置后仍可通过终局建筑快速恢复容量。
4. 作为 UI 用户，我希望军事面板/军力容量行显示「虫洞 LvX 军力容量 +Y%」与军械科技容量加成并列，以便理解容量来源构成。
5. 作为 UI 用户，我希望虫洞建筑卡描述文案包含军力线效果（军力容量每级 +10%），以便在建造前了解该建筑的全部收益。
6. 作为玩家，我希望升级虫洞不影响军力产出速率与攻占守卫（仍锚定产出），以便容量成长不抬升攻占门槛。
7. 作为玩家，我希望虫洞容量加成不进入 NG+ 遗产，以便新周目重新爬楼时保持既有周目语义一致。
8. 作为平衡观察者，我希望虫洞 Lv0 时军力容量与现状逐字节一致（无虫洞=不回归），以便升级前的存量行为不变。
9. 作为测试观察者，我希望军力容量公式的变化能通过现有 seam（`militaryCap` 纯函数）单点断言覆盖，以便主 seam 保持唯一。

## Implementation Decisions

- **引擎（核心）**：`militaryCap(state)` 公式追加独立因子 `(1 + WORMHOLE_CAP_PER_LEVEL × wormholeLv)`。虫洞等级读 `state.upgrades.wormhole ?? 0`——与 `generate.ts` 读 wormhole 的方式一致，不引 exploration 防环依赖。
- **根因子**：`balance.ts` 新增 `WORMHOLE_CAP_PER_LEVEL = 0.1`（每级 +10%，Lv10 封顶 ×2），与 `MILITARY_CAP_TECH_PER_LEVEL` 同族。
- **叠加语义**：与军械科技互为独立乘法因子（`×(1+0.1×军械) × (1+0.1×虫洞)`），不合并、不加算。
- **UI 展示**：军力容量展示行（`productionReport` 军力行的 `capNote` 或等价来源提示）追加「虫洞 LvX 军力容量 +Y%」，与军械科技容量行并列；虫洞建筑卡描述追加军力线文案（每级 +10%，Lv10 ×2）。i18n 中/英同步新增。
- **数据**：虫洞建筑定义（`data.ts`）无 schema 变更；描述 `descArgs` 若需新增格式化参数则同步扩展。

## Testing Decisions

- **好的测试标准**：只测外部行为——`militaryCap(state)` 作为纯函数输入状态、输出容量，不断言实现内部（不测公式拆解过程）；UI 测试断言渲染文案而非 DOM 细节。
- **主 seam**：`militaryCap(state)`（`src/engine/production.ts`）——引擎级纯函数，所有下游派生自它。新增断言：
  - 无虫洞（`upgrades.wormhole` 未定义/0）时容量与现状逐字节一致（回归保护）。
  - 虫洞 Lv1/Lv5/Lv10 下容量分别 ×1.1/×1.5/×2，与军械科技叠加正确。
  - 与现有断言共存：`production.test.ts` 军港容量断言、`balance-simulation.test.ts` 军械科技 ×1.5 断言、攻占守卫锚产出断言（守卫不随虫洞漂移）。
- **展示 seam**：`productionReport`/`productionBreakdown` 军力行 `capNote`——新增虫洞来源提示文案断言（参照 `production-breakdown.test.ts:160-167` 已有截断提示先例）。
- **先例**：`balance-simulation.test.ts` 中军力容量锚定（`(100 + 200×25) × 1.5 = 7650`）、`production.test.ts:21` 军港线性断言。
- **全量回归**：`pnpm test` 全量跑一遍，确认无其他模块（探索成本、胁迫门槛、自动攻占、raid）因容量放大断言漂移。

## Out of Scope

- 军力产出（兵营 0.5/s）随虫洞放大——明确不做（攻占守卫锚产出，放大产出自我抵消）。
- 每座兵营/军港的独立容量贡献（数量×等级耦合）——违反 ADR-0036，不做。
- 虫洞容量加成进 NG+ 遗产——不做（沿用 ADR-0042 周目语义）。
- 虫洞消耗豁免规则（容量加成部分不锚定消耗）——不做（Q3=A，接受 cost-anchors-cap 自洽缩放）。
- 新增军力系成就、新建筑、新科技——不做。
- balance-sim 新增虫洞专项长线模拟——可选 open item，本期不做。

## Further Notes

- **关联 ADR**：ADR-0042（虫洞探索线 → 追加军力线）、ADR-0036（机制二分——不引入数量×等级耦合）、ADR-0027（军械科技容量轴 → 虫洞成为第二轴）、ADR-0047（本决策）。
- **数值锚点**：虫洞 Lv10 ×2 时，满足满 20 槽探索（210k 军力、base=1000）所需军港从 ≈537 座降至 ≈268 座（乘数流 ≈1.95 假设）。
- **feature slug**：`wormhole-military-cap`。
