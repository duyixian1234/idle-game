# 舰队（能源消耗途径 · 防御系统）

**Status:** implemented

## Problem Statement

后期能源产出指数级膨胀（恒星阵列 `1000/s × 2^level`、冶炼场倍率、科技倍率叠加），但能源的持续消耗途径只有冶炼场一项指数级入口——**能源后期严重溢出**，能源作为资源的"取舍张力"消失：玩家全都要，不需要做任何选择。同时，派系骚扰（threat ≥55 未结盟派系周期性军事骚扰）在满声望下依然存在（阈值硬上限 65，铁卫 70 永远在阈值内），玩家只能反复用军力击退或付税，没有"建设性"的防御投资手段。

## Solution

新增**舰队系统**——第一个"能源持续消耗"的主动途径：

- 星港 ≥1 解锁「船坞」（unique 大件，Lv1-3），船坞等级决定舰队上限（Lv1=3 艘 / Lv2=6 / Lv3=10）
- 玩家可建造**护卫舰**：每艘成本与能源维护费**边际递增**（`base × 1.5^(n-1)`，n=现有舰数），规模 = 能源支出的可调开关
- 舰队提供**防御收益**：骚扰事件被舰队自动迎击（够强则不弹窗、直接结算为日志；不够强则弹窗但击退强度按舰队战力削减）
- **软降级**：能源不足以支付维护费时舰队停摆（自动迎击失效），恢复供能自动重启；购买/启用为硬约束（付不起不许买）
- 军械科技（militaryTech）降级为舰队威力放大器（每级舰队战力 +X%）
- 数值哲学：**策略取舍**——满编舰队维护费 ≈ 冶炼场升一级的代价（15~30% 产出），玩家在"生产（冶炼场/建筑升级）vs 军备（舰队）"之间做真实选择

存档升 **schema v8**（新增 `fleet.count`），迁移走 migrateSave 统一入口。

## User Stories

1. 作为中期玩家，我希望在星港建成后能解锁并升级「船坞」，以便拥有舰队的入口。
2. 作为中期玩家，我希望船坞等级决定我的舰队规模上限（3/6/10 艘），以便舰队规模有成长空间且受建筑链约束。
3. 作为玩家，我希望建造护卫舰需要矿物+能源且成本逐艘递增，以便舰队规模成为有代价的战略决策而非无脑买满。
4. 作为玩家，我希望舰队规模达到上限后不能再建造，以便规模上限是有意义的约束。
5. 作为玩家，我希望每艘护卫舰有持续能源维护费（逐艘递增），以便能源成为"生产 vs 军备"的取舍资源。
6. 作为玩家，我希望能源不足以支付维护费时舰队停摆而非崩溃，以便能源紧张时我有缓冲、不会永久失去舰队。
7. 作为玩家，我希望恢复供能后舰队自动重启，以便软降级是无痛且可逆的。
8. 作为玩家，我希望舰队自动迎击常规派系骚扰（够强时事件不弹窗、直接看到击退日志），以便舰队投资有持续的防御回报、减少重复弹窗操作。
9. 作为玩家，我希望舰队战力不足时骚扰事件仍弹窗、且手动击退所需的军力按舰队战力削减，以便高威胁派系（黑曜协议等）仍需要我手动决策。
10. 作为玩家，我希望离线时舰队维护费与自动迎击与在线同口径结算，以便离线行为可预期。
11. 作为玩家，我希望军械科技提升舰队战力，以便攻占链的科技投资在舰队时代依然有价值。
12. 作为玩家，我希望在星域页看到船坞与舰队的完整管理界面（当前舰数 X/Y、建造按钮、维护费与战力预览），以便我对能源支出有清晰认知。
13. 作为玩家，我希望舰队停摆时有明确警示（而非静默失效），以便我知道舰队为何不工作。
14. 作为玩家，我希望舰队在 NG+ 时随星际工程一并重置，以便新周目从零规划，遗产体系不膨胀。
15. 作为玩家，我希望旧存档（v7 及更早）自动迁移出舰队字段（默认 0 艘），以便更新后我的存档不丢进度。

## Implementation Decisions

### 数据模型

- `BuildingDef` 扩展 `maxLevel?: number`（仅 unique 建筑使用，限制升级上限；科技 TECHS 已有 maxLevel 先例）。船坞 = `category: 'interstellar'`、`unique: true`、`maxLevel: 3`，解锁前置 = 星港矿场 ≥1（`isBuildingUnlocked` 链式复用）。
- 舰数上限显式映射：`DOCK_SHIP_CAP = { 1: 3, 2: 6, 3: 10 }`（非等差，显式表）。船坞 0 级 = 无舰队。
- 新状态字段 `state.fleet: { count: number }`（周目内，NG+ 归零）。船坞等级派生自 `state.buildings.dock`，**不重复存档**。`powered` 为派生状态（每 tick 结算判定），不存档。
- 存档 schema v8：`fleet: { count }`（默认 0）。迁移链追加 `migrateV7ToV8`，schemaVersion **写死 SCHEMA_V8**（沿用 fixed-rng/exploration/interstellar 的防跳级教训），SAVE_SCHEMA 加一行字段说明。

### 舰队公式（纯函数，集中在引擎层）

- 第 n 艘购买成本（n = 1 起）：`mineral × SHIP_BUY_COST_BASE × SHIP_GROWTH^(n-1)` + 一次性能源 `SHIP_BUY_ENERGY × SHIP_GROWTH^(n-1)`；购买为**硬约束**（付不起不可点，与派遣/威慑同语义）。
- 维护费：`SHIP_MAINT_BASE × SHIP_GROWTH^(n-1)` 能源/s/艘；总维护 = Σ 各艘（几何级数求和）。
- 舰队战力：`fleetPower = count × SHIP_POWER_BASE × (1 + 军械科技倍率)`。
- `SHIP_GROWTH = 1.5`；`SHIP_POWER_BASE`、`SHIP_BUY_COST_BASE`、`SHIP_BUY_ENERGY`、`SHIP_MAINT_BASE` 归 balance-sim 定标（见 Further Notes 锚点）。

### 防御接线

- **在线自动迎击**：骚扰事件（defId='raid'）被选中后、生成事件卡前判定——`fleetPower ≥ strength` 则**不生成事件实例**，直接结算：威胁 −`RAID_THREAT_LOSS`、**不扣军力**（舰队代劳，成本即持续维护费），push 日志（`系统`级别，如「你的护卫舰队迎击了铁卫的骚扰舰群，威胁 −15」）。
- **残余弹窗**：`fleetPower < strength` 时事件照常生成，但 `repel` 选项所需军力 = `max(50, strength − fleetPower)`（残余部分需手动军力），hint 与结算口径一致。
- **离线同口径**：`settleOfflineRaids` 内自动判定优先消耗舰队战力（够强则自动迎击，不扣军力），不足则按现有"军力自动击退 / 否则按无视扣资源"回退；损失封顶 30% 规则不变。离线舰队维护费按整段硬扣（同恒星阵列 `applyMaintenance` 口径，可为负，回归 clamp 0）。

### 软降级

- tick 能源结算后判定：`energy ≥ 总维护费` → 扣费、`powered = true`；不足 → **不扣费**、`powered = false`（停摆：自动迎击失效、fleetPower 归零、骚扰退回手动弹窗）。供能恢复后下一 tick 自动 `powered = true`。
- UI 停摆警示：舰队分组显示「能源不足，舰队停摆」，禁用迎击状态说明。

### UI

- 星域页建筑面板新增「舰队」分组（interstellar 分组内船坞卡 + 舰队管理区）：当前舰数 X/Y、建造按钮（含第 n 艘成本预览）、总维护费与战力预览（`-X 能源/s`）、停摆警示。全部 `data-*` 语义化（`data-fleet-*`），E2E 断言不依赖样式类。

### 军械科技

- `militaryTech`（攻占虫群前哨解锁，Lv1-5）每级舰队战力 +`FLEET_POWER_TECH_PER_LEVEL`%（balance-sim 定标，锚点 ±10%）。

### NG+

- NG+ 重置：`fleet.count` 归零、船坞随 buildings 重置（星际工程同规则）；不设舰队专属遗产（permanentMult 已有全局继承）。

## Testing Decisions

- **主 seam（引擎纯 TS）**：沿用 `interstellar.test.ts`（unique 大件/解锁链）、`raid.test.ts`（骚扰判定）、`save.test.ts`（迁移链）先例。覆盖：船坞解锁链与 maxLevel 封顶、造舰成本曲线/上限硬约束、fleetPower 计算与军械科技倍率、在线自动迎击判定（够强不弹窗结算 / 不足削减残余强度）、软降级（停摆/恢复/不扣费）、离线同口径（整段维护费 + 自动迎击 + 封顶不变）、NG+ 重置、存档 v7→v8 迁移（写死 SCHEMA_V8、缺省补 0、幂等）。
- **次 seam（dom 冒烟）**：舰队分组渲染（船坞卡/舰数 X/Y/维护费预览/停摆警示 `data-fleet-*`），沿用 `dom.test.ts` 先例。
- **E2E（用户手动执行，agent 不跑）**：v7→v8 迁移、船坞解锁链（星港前锁定原因显示）、造舰至上限、自动迎击替代弹窗（事件卡不出现 + 日志出现）、停摆与恢复；复用 seedSave + lockSaveStore 注入技巧与「playing 档派系未统一」铁律。
  - **✅ 2026-08-06 用户手动验证全通过（e2e/fleet.spec.ts 5 用例），正式上线。**
- 好测试的标准：只断言外部行为（事件卡是否出现、资源扣减、日志文本语义），不断言内部实现细节（powered 字段名等）。

## Out of Scope

- 探索加速/护航（用户候选清单，下期独立 feature）
- 进攻向武器（攻占成功率、骚扰敌方等）
- 派系关系/外交新动作（威慑已有能源消耗先例，不扩展）
- 舰队除防御外的其他玩法（探索护航、运输等）
- 能源产出的削减（本期只加消耗途径，不动产出曲线）

## Further Notes

- 数值锚点（balance-sim 校准定稿，ticket 06；防回归断言入 `fleet.test.ts`）：
  - `SHIP_POWER_BASE = 1200`：Lv1 满编 3 艘 = 3,600 ≥ 铁卫 70 强度 3,500 → 可自动迎击；
    沃克斯 60（强度 3,000）在 2 艘（2,400）需军械科技 Lv3（×1.3 = 3,120）才够——科技改变判定边界
  - `SHIP_MAINT_BASE = 25`：Lv1 满编 3 艘 119/s（星港时代产出 ~4%）、Lv2 满编 6 艘 520/s（~18.5%，
    落 15~30% 取舍带）、Lv3 满编 10 艘 2,833/s（恒星阵列 Lv3+ 时代 ~16%）
  - `SHIP_BUY_COST_BASE = 100万` / `SHIP_BUY_ENERGY = 20万`：第 1 艘 ≤ 星港造价 1%（可负担），
    第 10 艘矿物 ×38.4（边际显著，取舍杠杆）
  - `FLEET_POWER_TECH_PER_LEVEL = 0.1`：满级 Lv5 = ×1.5 基础（与科技线节奏协调）
  - 节奏复核：满编维护 ≤ 当期产出 30%（不破产）硬约束通过（balance-sim 断言防回归）
- 骚扰系统「防御玩法永续」注释（balance.ts RAID_THRESHOLD_BONUS_CAP）是本设计的直接钩子：舰队是"减压阀"而非"终结者"，高威胁派系仍需手动决策，骚扰系统存活。
- 自动迎击不扣军力是刻意设计：舰队是军力按次消耗的**替代品**，其成本是持续维护费（能源）；两套军事资源各司其职，避免双轨数值纠缠。
- 命名：船坞（dock）/ 护卫舰（escort）/ 舰队（fleet）；成就与叙事文案实现期定稿（参照 endlessii 先例：同源谓词防数值漂移）。
