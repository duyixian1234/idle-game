# Spec: 科技升级与科技点消耗口扩展

## Problem Statement

科技点是游戏三种资源之一，但目前只有一次性消耗口：6 项科技全研发仅需 1,645 科技点（10+25+60+150+400+1000），研发完后科技点只剩「星球解锁阈值（累计约 6.2 万封顶）」「外交结盟（2 万）」两笔一次性开销和 NG+ 继承（2,000×等级）。挂机后期科技点只进不出，顶部资源条的「◎」沦为摆设，玩家感受是科技点用途不大。

## Solution

科技点获得持续消耗体系，核心是「科技升级」：5 项产出类科技可反复升级（Lv1→Lv10），每级线性提升产出系数、成本指数递增，科技点成为长期消耗品。同时新增三个辅助消耗口：外交行动消耗科技点（威慑加成本 + 新增「技术共享」行动）、矿物→科技点单向兑换（固定 100:1）、现有随机事件追加科技点支付分支（陨石雨防护罩、虫族警报神经干扰）。存档以迁移式升级（`researched: boolean` → `techLevels: Record<id, number>`），旧档无损。

## User Stories

1. 作为一名玩家，我希望已研发的产出类科技可以继续升级（如行星钻探 Lv1→Lv10），以便科技点有持续的消费出口。
2. 作为一名玩家，我希望升级科技每级都有明确的收益预览（当前系数 → 下一级系数），以便判断升级价值。
3. 作为一名玩家，我希望升级成本随等级指数递增，以便升级节奏有梯度、后期不秒升。
4. 作为一名玩家，我希望升级只作用于 5 项产出类科技（深层钻探等解锁类保持一次性），以便语义清晰、不做无新内容的重复升级。
5. 作为一名玩家，我希望科技有等级上限（Lv10），以便保护数值平衡与大数字显示。
6. 作为一名玩家，我希望旧存档自动迁移（已研发科技 = Lv1），以便已部署版本的进度不丢失。
7. 作为一名玩家，我希望科技面板显示每个科技的当前等级、下一级效果与成本，以便决策升级顺序。
8. 作为一名玩家，我希望科技面板提供「兑换」入口，将矿物按固定汇率（100:1）兑换为科技点，以便矿物溢出时有调度手段。
9. 作为一名玩家，我希望威慑行动消耗科技点（技术优势语义），以便科技点进入外交维度。
10. 作为一名玩家，我希望外交面板新增「技术共享」行动：花费科技点直接提升派系好感度，以便科技点有独立于资源的外交出口。
11. 作为一名玩家，我希望陨石雨事件出现「启动科技防护罩」选项（花费科技点减免损失），以便事件决策引入科技点。
12. 作为一名玩家，我希望虫族警报事件出现「神经干扰」选项（花费科技点替代矿物清剿），以便事件决策引入科技点。
13. 作为一名玩家，我希望 NG+ 继承策略维持现状（继承科技点、不继承科技等级），以便不破坏既有二周目节奏。
14. 作为一名玩家，我希望升级/兑换/外交/事件消耗的科技点数量与产出能力配平（实现后经模拟调参），以便升级全满在通关流程内可达而非遥遥无期。

## Implementation Decisions

- **科技等级模型**：存档字段 `researched: Record<id, boolean>` 迁移为 `techLevels: Record<id, number>`（0 = 未研发）；旧档 `researched[id] === true` 迁移为 `techLevels[id] = 1`；存档 schema version 升级，旧格式读取校验随之更新。
- **升级语义**：仅 5 项 `production` 类科技可升级（planetDrill / solarEfficiency / computingBoost / fusionCell / nanoFab）；`unlockBuilding` 类（deepDrill）保持一次性研发（level 恒 1，无升级入口）。
- **收益公式**：生效系数 = 基础 mult + 0.5 × (level − 1)，与现有建筑升级口径（`1 + 0.5 × level`）风格统一；例如行星钻探 ×1.5 → Lv2 ×2.0 → … → Lv10 ×6.0。产出管线复用现有 `productionMultipliers` 累乘逻辑，改为按等级取系数。
- **成本公式**：`cost(lv) = base × 1.5^(lv−1)`（lv 为当前等级），矿物与科技点同比例递增；Lv10 满级总成本 ≈ 75×base；5 项科技全满级合计约 11 万科技点，与外交/事件消耗同量级。研发动作保留现有校验链（资源/前置/重复），升级复用同一入口（已满级则拒绝并返回原因）。
- **兑换系统**：单向 矿物→科技点，固定汇率 100:1，无手续费、无兑换量限制；引擎提供兑换 action（校验矿物余额），UI 在科技面板底部提供兑换行（含一键最大）。
- **外交消耗**：威慑行动成本改为 矿物 3 万 + 能源 1.5 万 + 科技 1 万（原科技 0）；新增行动「技术共享」：20,000 科技点 → 好感 +15，与结盟成本同量级，纯科技点出口。外交好感/统一联邦判定逻辑不变。
- **事件分支**：陨石雨追加「启动科技防护罩」选项（科技点支付，减免损失）；虫族警报追加「神经干扰」选项（科技点支付，替代矿物清剿）。成本沿用现有 `scaledBy(产出, base, 步长)` 动态定标口径（以科技点产出为基准）。事件生成时按当前科技点余额决定选项可用性，余额不足禁用并提示。
- **NG+**：维持现状——继承科技点 2,000×NG+等级，`techLevels` 随 `researched` 一并重置为空（NG+ 从头研发）。
- **UI**：科技面板条目由「已研发 ✓」改为「Lv X」+ 升级按钮 + 下一级效果/成本；Lv10 显示「已满级」禁用；面板底部新增「兑换」区块（矿物→科技点，输入/一键最大）；外交面板新增「技术共享」行动按钮；事件选项 hint 标注科技点成本。均沿用现有 DOM 渲染与事件委托模式。
- **配平流程**：产出参数（实验室 0.5/s、轨道转换 30%）先不动；实现后用脚本模拟 5 项科技满级时长与科技点总需求，再决定是否上调实验室产量或轨道转换比例。

## Testing Decisions

- **seam**：沿用既有双层 seam——引擎层（纯 TS 零 DOM）Vitest 单元测试为主 seam，UI 层 jsdom 冒烟测试为次 seam；不新增 seam。
- **好测试的标准**：给定输入状态 + action，断言输出状态/渲染结果，不 mock 内部方法、不依赖 DOM 实现细节；离线/时间相关逻辑用注入时钟做确定性断言（现有先例）。
- **引擎层新增覆盖**：
  - 升级：`upgradeTech` 成功/余额不足/已满级拒绝；收益系数按等级正确（Lv1 与旧行为一致，Lv10 封顶）；成本公式随等级指数递增。
  - 迁移：旧格式存档（`researched` boolean）读入后 `techLevels` 正确且旧科技 = Lv1；全新档 techLevels 为空对象。
  - 兑换：`convertMineralToTech` 成功/余额不足；汇率 100:1 与取整。
  - 外交：威慑新成本（含科技 1 万）；「技术共享」成功/余额不足，好感 +15；统一联邦判定不受新行动影响。
  - 事件：陨石雨防护罩与虫族警报神经干扰分支（余额足/不足、结果正确）。
  - 回归：现有 139+ 测试不破（researchTech 行为与 Lv1 等价）。
- **UI 层覆盖**：科技面板 Lv 显示与升级按钮状态、兑换行渲染与点击、外交面板技术共享按钮、事件选项科技成本 hint。
- **先例**：`src/engine/*.test.ts`（引擎）与 `src/ui/dom.test.ts`（冒烟）为既有范式。

## Out of Scope

- 科技点双向兑换（科技点→矿物）与浮动汇率。
- 解锁类科技（深层钻探）的等级化。
- 新增一次性科技条目或新增随机事件种类。
- NG+ 继承科技等级或改继承策略。
- 科技点参与贸易行动成本（贸易仍纯矿物）。
- 数值配平的最终参数（实现阶段经模拟后另行提交调参）。

## Further Notes

- 设计经 batch-grill-me 三轮访谈定稿（2026-08-05），11 项决策全部经用户确认；「两者结合」为根决策。
- 科技升级天然形成正反馈（升级计算加速 → 科技点产出↑ → 更快升级），由 ×1.5 指数成本抑制，属可接受设计而非缺陷。
- 改动面：引擎（techLevels 迁移/升级/兑换/外交/事件）+ UI（科技面板/外交面板/事件卡片）+ 存档 schema + 测试；按 6 个 ticket 顺序推进，每步原子提交。
